O ciclo de TDD

1 · Vermelho

Escrever um teste que falha

O teste descreve o comportamento esperado antes de existir código para ele.

2 · Verde

Implementação mínima

Só o código necessário para o teste passar, sem adiantar funcionalidades.

3 · Refatorar

Limpar com os testes verdes

Melhorar nomes e estrutura sem mudar o comportamento que o teste garante.

No PetCare, cada defeito encontrado virou um ciclo: um commit só com o teste falhando (vermelho) e outro só com a correção (verde), às vezes seguido de um commit de refatoração.

Defeitos conhecidos ficam registrados como falha esperada: a suíte segue verde e o teste vira o vermelho do próximo ciclo.

Critério Conceito: explicar o ciclo com as nossas palavras. Vermelho: o teste é escrito primeiro e falha porque o comportamento ainda não existe. Verde: a menor mudança que faz o teste passar. Refatorar: melhorar o código com a rede de segurança dos testes. No repositório isso aparece como pares de commits: "test:" seguido de "fix:", e às vezes "refactor:".
